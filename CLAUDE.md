# @magic-spells/sticky-header

## Purpose

Scroll-following sticky header web component. `<sticky-header>` is the sticky container for everything that slides (announcement bar + header); it translates **1:1 with the scroll** rather than flipping between two states, and settles to fully shown or fully hidden only when scrolling stops. `<sticky-content>` is a rider that pins below the header and follows the same offset. A multi-bar stack can name a **reveal boundary** with `data-sticky-reveal`, which adds a third resting stop: layers above the boundary are top-only and return near the page top only. Wrapped mode is the only anatomy — everything that slides lives inside the host. Supports viewport gating (`hide-on-scroll` + `breakpoint`), lock conditions (`dialog[open]` built in, plus a `lock` selector), a configurable damped-oscillator settle with bounce, and a reduced-motion binary fallback. No dependencies, no Shadow DOM.

## Key files

- `src/lib/scroll-handler.js` + `src/lib/viewport-metrics.js` — **this package's own internal scroll-signal layer.** `ScrollHandler` is a module singleton owning the scroll SIGNAL and nothing visual: one set of window/visualViewport/load/pageshow listeners, one self-terminating rAF loop, `[0, maxScrollY]` position clamping, quiet windows, resize classification, velocity, movement-armed rest, and scroll-restoration adoption. `ViewportMetrics` reports `{ currentHeight, stableHeight }` off a `100svh` probe, falling back to the live viewport where `CSS.supports` is missing. Consumers subscribe with plain callbacks (`frame` / `rest` / `rebase` / `resize`) and get a per-frame packet; a `frame` callback returning `true` is what keeps the loop awake. **These files began as a would-be standalone `@magic-spells/scroll-handler` package and are now permanently part of sticky-header** (decision 2026-08-28: sticky-header was its only consumer, so it was folded in rather than shipped). There is no external package, no byte-identical discipline and no vendor-delta protocol — edit them like any other source file. The module BOUNDARY is still deliberately clean and extraction-ready in case a second consumer ever appears: the layer imports nothing from the rest of `src/`, knows nothing about headers, elements or CSS variables, and its export surface is pinned by `test/viewport-metrics.test.js`. Keep it that way, but do not contort anything to preserve a package that does not exist
- `src/lib/scroll-engine.js` — `ScrollEngine`, a module singleton: one offset value, subscribed to `ScrollHandler`. Owns the three stops, the settle tween, the motion state machine, glide mode, state attributes, and rider `[stuck]`. It no longer owns any listener, the rAF loop, `scrollY` reads or clamping, `maxScrollY`, quiet windows, the idle timer, or restore adoption — all of that moved to the handler
- `src/lib/easing.js` — damped harmonic oscillator step response; `makeSettleEase(overshoot)` plus the `SETTLE_LINEAR_CURVE` doc constant
- `src/components/sticky-header.js` — `StickyHeader`: attributes, measurement, media gating, locks, the reveal boundary, events, public API
- `src/components/sticky-content.js` — `StickyContent`: a rider; caches its resolved base inset, everything else is CSS
- `src/styles/sticky-header.css` — all styling. **Contains no transitions, deliberately**
- `src/index.js` — entry: imports CSS, named exports of both classes plus `SETTLE_LINEAR_CURVE` / `makeSettleEase`
- `demo/index.html` — manual test page: a three-layer group (untagged countdown + `data-sticky-reveal="mobile"` announcement + bare-tagged header), a collapsed-by-default control panel and a live readout with reveal + threshold markers (port 3090 in dev). The panel also carries the one on-device A/B lever, a `tracking-smoothing` radio (off / 20 / 35 / 50 ms). The page imports nothing from the bundle — it drives the header through attributes alone. Content below is unlabeled placeholder blocks, there only as scroll runway. Pulls two sibling packages from the unpkg CDN at pinned versions — `@magic-spells/split-text@0.2.0` (hero) and `@magic-spells/dropdown-panel@1.0.0` (header dropdown, which also drives the `lock` selector demo via `dropdown-component[visible]`). House rule: cross-package usage goes through published npm builds, never `file:` links or vendored copies
- `scripts/build.mjs` — Vite + Rolldown build, copied from split-panel

## Architecture

**0. The scroll SIGNAL comes from `ScrollHandler`, not from the engine.** Window/visualViewport/load/pageshow listeners, the rAF loop, `scrollY` reads and `[0, maxScrollY]` clamping, quiet windows, velocity, movement-armed rest and scroll-restoration adoption all live in the signal layer (`src/lib/scroll-handler.js`). The engine subscribes once (`frame` / `rest` / `rebase` / `resize`) and gets a per-frame packet — `{ y, rawY, delta, velocity, dt, now, quiet, reducedMotion }` — that is already correct on mobile. `frame` returning true is what keeps the loop awake, replacing the engine's own `tick()` at the end of a frame; `ScrollEngine.tick()` now forwards to `sub.tick()` and `ScrollEngine.rebase()` to `ScrollHandler.rebase()`. Everything below is what the engine adds ON TOP of that signal. The engine keeps exactly one listener of its own, on `prefers-reduced-motion`, because a preference flip has to cancel a tween and re-anchor — a reaction to a preference, not to a scroll.

**0a. The signal layer's own invariants**, ported from its standalone README and pinned by `test/`:

- **Every subscriber in a frame gets the SAME packet object**, and the handler takes its one `scrollY` read before any callback runs — so no consumer can shift the ground under the next one.
- **Everything is time-constant based, not per-frame based.** A `* 0.76` per-frame decay runs twice as often at 120Hz and kills a flick twice as fast per millisecond of real time. The reference constants were tuned at 60Hz and are CONVERTED rather than replaced, so the 60Hz feel is unchanged and every other refresh rate now matches it: `VELOCITY_DECAY_TAU = −16.667 / ln(0.76) ≈ 60.73ms`, `EMA_TAU = −16.667 / ln(0.85) ≈ 102.55ms`. `expApproach(current, target, dt, tau)` is the shared primitive — it is what `tracking-smoothing` uses.
- **Resize classification is by `window.innerWidth`, and is fixed behavior with no toggle.** Width changed → a real resize/rotation, layout moved, so a delta across it is meaningless: quiet window + `rebase('resize')`. Height only → almost always mobile chrome (URL bar or soft keyboard), the scroll position is still the user's, so it never quiets and **deltas stay live**. Quieting height-only resizes was the original behavior and on-device testing (real iPhone) killed it: iOS toggles the URL bar on nearly every scroll direction REVERSAL, so every reversal opened a quiet window that zeroed and rebased away real deltas, freezing tracking for ~70–100px per reversal — far worse than the phantom deltas it was guarding against. Should phantom deltas ever resurface somewhere, the fix belongs inside this normalization, not in a consumer-facing flag.
- **Constants**: `MAX_FRAME_DELTA=64` (ms ceiling — a backgrounded tab's wakeup frame becomes a bad frame, not one enormous easing step), `FIRST_FRAME_DELTA=16`, `IDLE_MS=120` (rest fallback where `scrollend` is missing), `RESIZE_QUIET_MS=100`, `MAX_VELOCITY=100`, `VELOCITY_THRESHOLD=0.01` (below it velocity snaps to exactly `0`), `REFERENCE_FRAME_MS=1000/60`.
- **The loop is self-terminating and a thrown subscriber cannot kill it** — errors are caught and logged so one consumer can't stop frames for everyone else. It re-arms only while something moved this frame, velocity survives, or a subscriber returned `true`.
- **Nothing is touched at import time.** No listener is bound and no loop starts until the first `subscribe()`; the last `unsubscribe()` puts it back to sleep with nothing bound. The module must stay importable in Node — which is also what lets the suite run under jsdom.

1. **One number is the entire public interface between JS and CSS.** JS never writes `transform`. Every frame it computes an offset in px and writes `--header-group-offset` on `<body>`; the header, every rider and any author element are pure CSS readers of that variable. This is what makes the `position: fixed` descendant gotcha _fixable_ by the author (see Gotchas) — the translate can be moved to any element without touching JS.
2. **No CSS transitions anywhere.** The settle is a JS rAF tween of the _same_ variable that tracking writes. That removes the whole "suppress the transition while tracking" problem, and makes cancelling a settle exact: the offset is already where the tween left it, so tracking resumes from there with no snap.
3. **Motion is a three-state machine** — `idle` / `tracking` / `settling` — held on the engine, and **both entering and staying in `tracking` require a non-zero delta.** The frame callback only asks for another frame while `settling`, or while `tracking` _with_ movement this frame (plus the two pending-work cases in #19/#20). Both halves matter: a zero-delta frame (a resize, a ResizeObserver, an attribute change, a lock mutation, a rider registering — and now the handler's own velocity tail, which keeps the loop awake ~400ms after a flick) would otherwise enter tracking, set `body[data-header-tracking]`, and re-tick itself forever. A zero-delta frame instead lets the loop sleep; the handler's armed rest, or the next scroll event, wakes it to finish the job.
4. **Rest is driven by MOVEMENT, not by scroll events — and the handler owns it now.** `ScrollHandler._armIdle()` fires from its `onScroll` and, crucially, from its `onFrame` on every non-zero delta. Arming only from scroll events is a real bug that was caught in browser testing: a scroll event can land a frame _before_ the delta it describes, so the rest it arms fires, starts a settle, and the trailing delta then cancels that settle — with nothing left to re-arm, the header sits stranded mid-travel forever. **`cancelSettle()` therefore no longer arms anything, and does not need to:** its only caller is the frame branch that sees `|delta| >= 1`, and the handler already armed rest from that same delta in its read phase, before any subscriber ran. A rest is always already owed. This is also what makes iOS momentum work, and why a smooth anchor scroll never fights a settle.
5. **Three resting stops, one shared offset.** `0` (full stack), `−topOnlyHeight` (revealed), `−groupHeight` (hidden). `topOnlyHeight` is the offset of the **topmost currently-active `[data-sticky-reveal]` element** from the group top, measured as `boundaryRect.top − hostRect.top` — a rect DIFFERENCE, because the tag sits on a section's inner root inside an uncontrollable `.shopify-section` wrapper (nesting-proof) and because both rects carry the group transform equally (translate-invariant). That second premise holds only while the HOST is the translating element: under the documented `position: fixed` workaround (`transform: none` on the host, translate on an inner element) the boundary rect carries the offset and the host rect does not, so `#measureRevealHeight()` takes `ScrollEngine.offset` back out under the same `getComputedStyle(host).transform === 'none'` test `_pinned()` uses. Without it, a re-measure while hidden reads `true − groupHeight`, clamps to `0`, and publishes "nothing tagged" — the three-stop model collapses until the next measure at rest. No tags → `0`, which collapses the model back to the original two stops exactly. Tags present but none active at this breakpoint → `groupHeight`, so the reveal stop coincides with hidden and a mid-page scroll up reveals nothing. Mid-page tracking clamps `[−groupHeight, ceiling]` where **`ceiling = min(0, max(−topOnlyHeight, offset))`** — the reveal stop is a ceiling the group can only ever ratchet DOWN to, which is what stops the offset snapping by `topOnlyHeight` the instant the reveal threshold is crossed with the stack fully shown. The idle settle threshold brackets the two stops either side (`(upper − offset) / (groupHeight − topOnlyHeight)`), not the full travel; when the two coincide the only legal mid-page stop is hidden.
6. **Mode 2 is position-based, not direction-based.** Where `hide-on-scroll` is INACTIVE but a boundary sits strictly inside the group (`0 < topOnlyHeight < groupHeight`), the offset is written each frame as `−clamp(y − revealAnchor, 0, topOnlyHeight)`: the tagged bars leave with the page and return at the exact scroll position they left, while the header stays pinned. `revealAnchor` is the y at which the group last pinned — it can NOT be recovered from a rect once pinned (a pinned element's untranslated top is `stickyTop` at every y), so it is carried: set to `y` on every unpinned frame, rebased as `y + offset` in `rebase()` and under a forced tween, and — the case that actually bites — **re-synced to `y + offset` on every NON-glide frame**. A lock suspends the glide and force-shows; without that sync the first unlocked frame would jump the group by the whole boundary. On a restore path the anchor is instead seeded at `0`, because a restored position is not a gesture and the glide is absolute: a bar with no reason to stay pinned belongs exactly where the page put it. The strict-inside gate matters: with no active tag the boundary is the group bottom, and gliding there would scroll the whole header away on a viewport whose whole point is that it never hides. `disabled` opts out entirely.
7. **A general safety clamp, `offset >= −y`, in every mode.** The group can never hide more pixels than have been scrolled — otherwise it translates out of a flow slot that is still on screen and opens a gap above the page content. Applied after the mode branches, so it trims a hide settle rather than fighting the reveal-zone settle to `0` (`0 >= −y` always) and never touches the positive show overshoot.
8. **Strict read → compute → write batching in `onFrame`.** All reads first (`scrollY`, `_trackable()`'s rect, every rider's rect), then the offset math, then all writes (`--header-group-offset`, state attributes, rider `[stuck]`). Riders are read and written in two separate passes so a `[stuck]` toggle can't invalidate the next rider's rect read. Nothing that runs after the writes reads layout: `onStopsChanged()` only raises `stopsDirty`, and the decision it defers (`_applyStops()`) runs in the NEXT frame's compute phase off that frame's own `pinned`/`trackable` reads. `_measure()` follows the same shape — the boundary rects are read before the height vars are written, with the incoming group height passed in.
9. **The settle curve is a damped harmonic oscillator step response**, sampled over normalized tween progress fed in as seconds with ωn = 12. `settle-overshoot` is inverted into a damping ratio (ζ = −ln M / √(π² + ln²M)); `0` swaps to the critically damped form. Every curve is normalized by its own value at t = 1 so it lands exactly on 1 and the final frame never snaps. The default 5% overshoot gives ζ ≈ 0.690, peaking at t ≈ 0.36 (verified numerically). `SETTLE_LINEAR_CURVE` documents that default curve — **regenerate it if the default overshoot ever changes**, it is not derived at runtime.
10. **Tween timing is wall-clock, off the rAF clock.** `settle.start` is deliberately left `null` at creation and stamped by the first frame from its own `now`. Seeding it with `performance.now()` instead mixes two clocks — the rAF timestamp can be _earlier_ than the `performance.now()` taken moments before it, which yields a negative `t` on the first frame. Wall-clock (rather than accumulated frame deltas) is what makes a background-tab wakeup clamp `t` to 1 and finish, instead of replaying the tween.
11. **Riders use a MOVING sticky inset, not a transform**: `top: calc(var(--sticky-content-top, var(--header-group-height)) + var(--header-group-offset))`. The browser pins at `max(flowTop, base + offset)` with no JS help, and because the inset itself moves, the pin position is continuous at every scroll position. A transform gated on a stuck flag is the alternative, and it makes a rider that first pins while the header is already hidden jump by the entire offset. JS contributes only the cached base inset and the `[stuck]` attribute. `rider._baseTop()` recovers the base by subtracting the offset from the resolved computed `top` (which already includes the calc) — and it subtracts **`ScrollEngine.lastWritten`, not the live `ScrollEngine.offset`**. The two diverge whenever the offset has been recomputed but its var write hasn't landed: a re-measure re-clamps outside the frame, so a cache resolved in that window would bake the difference in permanently (an announcement dismissed while hidden left every rider's base ~34px off).
12. **The engine owns motion; the element owns DOM knowledge.** The engine never reads attributes — it pulls through `_`-prefixed accessors on the host (`_config`, `_geometry`, `_isActive()`, `_isLocked()`, `_measure()`, `_emit()`). Swapping the positioning mechanism or the element's attribute surface stays a contained change.
13. **Measurement uses `offsetHeight`** (transform-independent, unlike `getBoundingClientRect`), via a `ResizeObserver` on the host + the `data-announcement` child. The child is **re-queried at the top of every `_measure()`**, as a read: a Shopify section re-render REPLACES that node rather than resizing it, and a cached detached node measures 0 — which would publish `--announcement-bar-height: 0px` and fold the whole group into `--header-height`, with the live node unobserved. When the node actually changed, `#observeTargets()` is re-run; it disconnects first, so no observation of the detached node leaks. Toggling `hidden` on the SAME node is the dismiss path and was always correct. `stickyTop` comes from the host's own resolved `top`, so a custom sticky inset is honoured by the pinned test. A 1px `HEIGHT_EPSILON` stops resize storms from rewriting variables, and the first measurement always publishes. On change the offset is re-clamped to the new range — an announcement dismissed while the header is hidden slides it partly back in rather than leaving it parked off-screen.
14. **Lock watching is as narrow as correctness allows.** A `MutationObserver` on `documentElement` with `attributeFilter: ['open']` covers the built-in `dialog[open]` rule; extra attribute names are parsed out of the author's own `lock` selector with a regex, and `class` is added _only_ when the selector actually uses one — a blanket attribute observer would wake the loop on every unrelated attribute write on the page. `childList: true` is **not** optional though: a `<dialog open>` inserted already-open, or a lock target conditionally rendered by a framework, fires no attribute mutation at all and would never be noticed. The handler is just a dirty flag plus a tick, so the extra notifications are cheap, and `_isLocked()` costs nothing per frame behind that flag.
15. **`hover-lock` rides on `pointerenter`/`pointerleave`, which do not bubble** and treat an element plus its whole subtree as one region — exactly the wanted semantics, so anything rendered inside the header (an open dropdown panel included, being a DOM child) counts as "in the header" with no extra wiring. The whole sliding group is inside the host, so one `pointerenter`/`pointerleave` pair on the host covers it and hovered state is a plain boolean. It is evaluated OUTSIDE the `#lockDirty` cache — hover changes on its own schedule with no mutation for the observer to see. Leaving needs no rebase: `lastScrollY` keeps updating every frame while locked, so no phantom delta accumulates.
16. **Three targeted mobile guards instead of a `100svh` probe** (all geometry is scroll deltas + element heights, so no viewport-height measurement is needed): `y` is clamped to `[0, maxScrollY]` (kills iOS rubber-band at both ends), a 100ms `RESIZE_QUIET_MS` window zeroes deltas and rebases after `resize` / `visualViewport.resize` (URL-bar storms), and the 1px height epsilon absorbs re-measure noise.
17. **`maxScrollY` is cached, refreshed lazily** — on resize, at the start of a scroll gesture, and whenever `y` exceeds the cache (a grown page or a bottom rubber-band). Reading `scrollHeight` every frame would force layout.

18. **Reveal tags are re-queried live, off a second `MutationObserver`** scoped to the host subtree with `childList: true` and `attributeFilter: ['data-sticky-reveal']`. Both halves are needed: the Shopify theme editor re-renders a whole section when its settings change (childList), and a tag value can be edited in place (attributes). Nothing the component writes is inside the observed set, so it cannot wake itself. The handler ONLY marks `#revealDirty` and ticks — measuring inline would force layout at microtask time, outside any frame. The measurement is dirty-gated in `_readReveal()` and the var write in `_writeReveal()`, so the engine takes the reads in its read phase and the write in its write phase, and a burst of records costs one re-measure. `#measureRevealHeight()` returns the boundary **unrounded** and `_readReveal()` rounds only at the publication point — rounding at the source would make every distinct measurement differ by a full pixel, and the 1px epsilon that guards against subpixel jitter around `x.5` could never absorb anything. `childList` + `subtree` is broad enough to fire on ordinary text churn (a cart count ticking over), so records are filtered to attribute edits and ELEMENT insertions/removals — a text-node swap can't move a boundary.

19. **`tracking-smoothing` is a PUBLICATION-boundary effect and nothing else.** The state machine, the thresholds, the three stops, `revealAnchor` and `reducedAnchor` all still run on the raw 1:1 `offset`; only the number written to `--header-group-offset` is eased toward it, as `published = expApproach(published, offset, dt, tau)` — and only while `motion === 'tracking'` (direction-based tracking AND the glide). Never during a settle, which is a tween that is already smooth and must not be smoothed twice; and `published` snaps to `offset` at idle, so **every resting stop is landed on exactly**. `tau = 0` (the default) resolves to the raw value outright, which is the whole opt-out. The hand-off runs the other way at settle start: `requestSettle()` adopts `published` into `offset` before taking the tween's `from`, because the group is visually AT `published` — that is what makes the two reconverge with no snap, and it is a no-op with smoothing off. `reclamp()` clamps `published` too, and because the safety clamps in `onFrame` constrain the RAW offset only, the smoothed candidate is re-clamped to the same constraints — `[−groupHeight, 0]` and `>= −y` — immediately before it is written, gated on `tau > 0` so a settle frame's deliberate show overshoot is never touched (without it, a fast scroll up from hidden near the page top publishes below the `offset >= −y` floor for several frames and opens a gap above the content). Because the two numbers can now differ, **anything that takes an applied transform back OUT of a rect must read `ScrollEngine.appliedOffset`** (`lastWritten`, or 0) rather than the raw offset: `_pinned()`, `_readRiders()`'s `effectiveTop`, and the component's `#measureRevealHeight()` carry correction. `sticky-content._baseTop()` already used `lastWritten` and is unchanged. The loop is held awake until `|published − offset| <= WRITE_EPSILON` so the published value can never park a fraction short.
20. **A settle COMPLETING is not movement, so it cannot rely on the handler's rest.** The re-check of the stop a tween actually landed on — a forced show that outlived a short gesture can leave the group at `0` mid-page, an illegal stop once anything is tagged — used to be an `armIdle()` at the end of `_stepSettle`. It is now a `restDue` flag, consumed by the next frame with **no movement in it** (`delta === 0` and not already settling) and held open by the frame keep-alive. Gating on a zero delta matters: consuming it mid-gesture would inject a settle that the very next delta cancels anyway, costing a frame of 1:1 tracking. It also answers the question in the compute phase off reads already taken, where the old path took a rect read off-frame. Net behavioral difference: the re-check lands ~1 frame after the tween instead of ~120ms after it, so `show()` mid-page still tucks to the reveal stop, just sooner.

## API

- **`<sticky-header>` attributes** (all observed): `hide-on-scroll` (`none|mobile|desktop|both`, default `both`), `breakpoint` (px, `1024` — one `(min-width: bp)` query, negated for `mobile`), `reveal-threshold` (px, `100`), `settle-threshold` (`0`–`1`, `0.5`), `settle-duration` (ms, `900`; show uses ×0.85), `settle-overshoot` (`0`–`0.2`, `0.05`), `tracking-smoothing` (ms time constant, `0`–`1000`, default `0` = off — eases only the PUBLISHED offset while tracking; see Architecture #19), `hover-lock` (boolean), `lock` (selector), `locked`, `disabled`
- **Descendant attributes**: `data-sticky-reveal` (`both|mobile|desktop|none`, or bare = `both`) on ANY descendant — the topmost active one is the reveal boundary. `none` is explicitly INACTIVE (a Liquid setting will often render the string rather than omit the attribute), and any unrecognized value is inactive too with a one-time `console.warn` — failing that way keeps the layer top-only instead of letting a typo pin the whole stack. `data-announcement` still reports its child's height separately
- **`<sticky-content>` attributes**: `top` (any CSS length — sugar for `--sticky-content-top`, and it owns ONLY the inline declaration it wrote: an author's own inline value is captured, left in place, and restored when the attribute is removed or the element disconnects), `disabled`
- **Properties/methods**: `offset`, `progress` (full travel), `revealOffset` (the reveal stop, `0` with nothing tagged), `isHidden`, `groupHeight`, `show()`, `hide()`, `lock()`/`unlock()`, `refresh()`. `<sticky-content>` exposes `stuck` and `top`. **`isHidden`, never `hidden`** — a `hidden` getter shadows the native `HTMLElement.hidden` boolean-attribute property and throws on assignment
- **Also exported**: `makeSettleEase(overshoot)` and `SETTLE_LINEAR_CURVE`, for authors matching the curve in their own animations
- **Body custom properties**: `--header-group-height`, `--header-height`, `--announcement-bar-height` (the `data-announcement` child; measured and maintained in every mode at every breakpoint), `--header-group-offset` (per frame, the public rider hook), `--header-reveal-offset` (−topOnlyHeight, republished only when the boundary moves)
- **State attributes**: `body[data-state="top|scrolling"]` (8px), `body[data-header-hidden]` (settled only), `body[data-header-revealed]` (settled at the reveal stop, and only while `0 < topOnlyHeight < groupHeight`), `body[data-header-tracking]`, `body[data-header-locked]`, `sticky-header[data-hidden]`/`[data-tracking]`, `sticky-content[stuck]`
- **Events** (bubble, on the host): `sticky-header:settle` `{target, from, duration}`, `sticky-header:hide`, `sticky-header:show`, `sticky-header:reveal` (settle-completion at the reveal stop; `hide`/`show` still track FULL hiding only, so returning from hidden to the reveal stop fires both `show` and `reveal`), `sticky-header:resize` `{headerHeight, announcementHeight, groupHeight}`. **No per-frame events** by design — read `offset`/`progress` from your own loop

## Conventions

- Engine constants: `TOP_THRESHOLD=8`, `BINARY_DELTA=5`, `WRITE_EPSILON=0.05` (a SETTLE guard only — `_writeOffset()` applies it while `motion === 'settling'` and nowhere else, so tracking writes every numerically changed value and a finished settle, being idle, still force-publishes its exact resting value), `SHOW_DURATION_SCALE=0.85`, `HEIGHT_EPSILON=1` (in the component). `IDLE_MS=120` and `RESIZE_QUIET_MS=100` moved to the handler with the timing they describe, and are re-exported from `scroll-engine.js` so the module surface is unchanged
- `handlers = {}` object of bound refs; `queryDOM()` holds the querySelector calls; `attachListeners()` binds
- `const _ = this` alias when a method references `this` 4+ times
- `#` private fields in the **classes**; the engine is an object literal, so its internals use `_` prefixes — `#` is a syntax error on an object literal, which the build catches loudly
- Registration guard `if (!customElements.get(...))`, named exports only, no Shadow DOM
- Events namespaced `sticky-header:*`, `bubbles: true`; state via attributes; rem units in CSS
- Both elements defer init to `DOMContentLoaded` when they upgrade before their children parse

## Gotchas

- **The background must be on `<sticky-header>` itself.** The show settle overshoots ~3% _past_ rest, pushing the header down and opening a gap above it. `sticky-header::before` covers that dip with `background: inherit` over a 2rem cap. A background on an inner element leaves the cap transparent and page content shows through the bounce — restate it on the pseudo-element, or set `settle-overshoot="0"`.
- **Hide-side overshoot is free, show-side is not.** Both directions use the same curve; off-screen overshoot costs nothing, which is the only reason one curve works for both.
- **The tween is not clamped to the travel range** — clamping it would destroy the bounce. Only _tracking_ clamps to `[-groupHeight, 0]`.
- **`position: fixed` descendants** get the transformed header as their containing block and are dragged along. Documented fix: `transform: none` on the host, translate an inner sibling instead. This works only because JS writes a variable, never a transform — and because `_pinned()` detects the swap (see below).
- **`overflow: hidden` on any ancestor kills `position: sticky`** — a CSS rule, not something the component can detect or fix.
- **`body[data-header-hidden]` is only ever evaluated at rest** (`motion === 'idle'`), and frozen mid-motion. That is what keeps a flick that momentarily clamps to −groupHeight from announcing a hide, and what makes `sticky-header:hide` / `:show` fire on _completion_ rather than the instant a settle starts moving. It is not a "scrolling down" signal — use `data-header-tracking` or `progress`.
- **`_trackable()` tests the UNtranslated top**: `rect.top - offset <= stickyTop + 0.5`. `getBoundingClientRect` already includes the transform, so the offset has to be taken back out or the check oscillates on the show overshoot. But **the host may not be the translating element** — the documented `position: fixed` fix sets `transform: none` on it — so `_pinned()` reads `getComputedStyle(header).transform` and subtracts nothing when it is `none`. The package rule always resolves to a matrix (`translateY(0px)` included), so `none` identifies that workaround exactly. Read per frame, in the read phase, because the rule can be breakpoint-dependent; without it the pinned test is false the whole time the header is hidden and every frame force-shows it.
- **A programmatic `scrollTo` of more than the group height hides the header in one frame.** That is correct 1:1 behavior (direction decides), not a bug — it surprised the first round of browser testing.
- **Don't arm idle detection only from `onScroll`** — see Architecture #4. This is the single subtlest correctness point in the engine.
- **`rebaseOnNextScroll` is armed only while `document.readyState !== 'complete'`.** It exists so browser scroll restoration is adopted rather than treated as a gesture, and `load`/`pageshow` are the only things that clear it — neither of which fires again for a header mounted after them (SPA, late upgrade). Arming it unconditionally leaves it set forever, so the first real scroll (a one-shot `scrollTo` included) rebases into a zero delta and is eaten; on a tagged stack idle then tucks the stack ~120ms later. A post-`load` mount has already adopted the position from `registerHeader()`'s own `rebase()`.
- **A rejected duplicate `<sticky-header>` must be inert on its API too.** `#initialized` stays false when the engine refuses a second host, and `show()` / `hide()` / `refresh()` early-return on that — otherwise `hide()` requests `-0` from the duplicate's empty geometry and SHOWS the live header, and `refresh()` hands `new ResizeObserver` a handler that was never bound. `lock()` / `unlock()` are deliberately NOT guarded: they only write the `locked` attribute, which `#init()` honours whenever it runs, and guarding them would silently drop a `lock()` issued before init — the package as a blocking `<head>` script defers init to `DOMContentLoaded`, so author code in a deferred or module script runs first, which is exactly the lock-before-jump pattern the README recommends.
- **`hover-lock` must be gated to `(hover: hover) and (pointer: fine)`.** On touch, `pointerenter` fires on tap and no `pointerleave` follows, so an ungated hover lock wedges the header open for the rest of the session.
- **A tagged element with no box is skipped.** A bar removed with `hidden` (or any `display: none`) has an all-zero rect, and taking its `top` would put the boundary at the negative host offset. The next active tag down becomes the boundary instead, which is also what makes toggling the announcement bar behave.
- **Mid-page the group cannot rest at `0` once anything is tagged.** `_settleTarget()` picks between the two bracketing stops only, so stopping just past the reveal threshold with the stack fully shown settles to the reveal stop — the top-only layers tuck away rather than staying up. That is the feature, not a stray settle. It also means **`show()` does not HOLD mid-page**: it plays the show tween, `_stepSettle` arms idle on completion, and idle retargets to the reveal stop. `lock()`/`unlock()` is the API that holds visibility, because `_trackable()` is false while locked. The README says so.
- **The dev server can serve a STALE `demo/dist` bundle.** The watch build rewrites `demo/dist/*.js` correctly, but the long-running Vite dev server has been observed serving the previous contents of those files over HTTP indefinitely — `curl localhost:3090/dist/sticky-header.esm.js | grep <new symbol>` returns nothing while the file on disk has it. Automated checks then silently test the OLD build and "pass". Verify the SERVED bytes before trusting a browser measurement; the cheap workaround, which also avoids disturbing a dev server that is live-reloading to a phone, is a plain static server on another port (`python3 -m http.server 3099 --directory demo`).
- **`revealOffset` is negative** (it is a stop on the same axis as `offset`), and `−0` is avoided explicitly so the readout never prints one.

## Verified in-browser

Playwright against the demo: 1:1 tracking (10px scroll → exactly 10px offset, both directions), settle commit either side of the threshold (70% → hidden, 40% → shown), a measured **+1.16px** show overshoot on a 39px travel (≈3%), `data-header-tracking` clearing at rest, the far-down rider approaching its pin with the header hidden at a **max 10px per-frame move** (i.e. exactly the scroll step — no jump), `dialog[open]` locking, announcement dismissal while hidden re-clamping −99 → −65, `hide-on-scroll="none"` keeping variables while never hiding, `data-state` flipping at 8px, and `show()`/`hide()`.

Reveal boundary (this feature), on the demo's countdown + announcement + header stack (group 129px): desktop boundary resolves to the header (**−64px** = countdown 30 + bar 34), mobile to the bar (**−30px**); exact **10.00px** 1:1 tracking preserved; the bracketed settle threshold committing both ways on a partial boundary (20px scroll up → back to hidden at 0.69 of the bracket; 50px up → the reveal stop at 0.23, where the OLD full-range rule would have hidden); `data-header-revealed` + a single completion-timed `sticky-header:reveal`; the untagged countdown never returning mid-page at either breakpoint; a rider landing **99.0px** against a group bottom of **98.9px** at the reveal stop; the position-based glide measuring `−min(y, 64)` exactly in both directions with the header pinned throughout; live tag edits re-resolving (`desktop`→−30, `mobile`→−64, removed→−64); the none-active case parking at −129 and revealing nothing mid-page; the safety clamp holding `offset >= −y` at every small y; and the no-tags regression settling to hidden on the same 50px move that reveals when tagged.

After the ScrollHandler refactor (desktop 1280, group 129px), re-verified: exact **10.0000px** per 10px scrolled in both directions; settle committing to **−129** at 0.69 of the bracket and **−64** at 0.23; reveal boundary **−64** desktop / **−30** mobile; `data-header-tracking` clearing at rest; `hide()` → −129 and `show()` → 0 then idle retargeting to −64 (Architecture #20); glide mode measuring exactly **−min(y, 64)** both directions.

With `tracking-smoothing="35"`: the published value trails the raw offset by a steady **6.2px** while tracking (**4.34px** at `tau=20`, **0** with it off) and both land on exactly **−129.0000 / −64.0000 / 0.0000** at rest; the published step across a mid-flight settle cancel is **0.000px**; the rider toggles `[stuck]` exactly **once** over a 90-step scroll pass, identical to smoothing off.

**Settled on-device (real iPhone, 2026-08-28): height-only resizes NEVER quiet, and there is no option.** Quieting them froze tracking for ~70–100px on every iOS URL-bar toggle, and iOS toggles the bar on every scroll direction REVERSAL, so each reversal opened a 100ms quiet window that zeroed and rebased away real deltas; live deltas are near-immediate with no phantom-delta artifacts. It is fixed behavior rather than a flag because normalizing scroll across desktop and mobile is the point of the handler, and a normalization layer has opinions, not toggles — if phantom deltas ever surface, the fix belongs inside the handler. Width-change resizes (rotation, real resizes) still quiet and rebase in full.

**Not yet verified — needs a real device:** iOS momentum and rubber-band, rotation mid-hide, `prefers-reduced-motion` binary behavior, and whether `tracking-smoothing` is worth having at all (the demo's radio is the A/B lever for that call; the default stays `0` until a device says otherwise).

## Unit tests

`test/` covers the signal layer only — 58 tests over 7 files, run with vitest under jsdom. It came in with the layer itself when the standalone package was folded in. Nothing in it depends on a real clock, a real rAF or a real layout: `test/harness.js` installs a fake `requestAnimationFrame` that CAPTURES the callback instead of scheduling it, so **every frame is fired by hand with an explicit dt** — which is what lets one test run the same wall-clock span at 60Hz, at 120Hz and through a dropped-frame pattern and assert all three agree. It also runs one fake clock shared by `performance.now()` and vitest's fake timers, so the rest fallback fires at the right simulated moment.

The handler is a module singleton, so every test tears its environment down and calls `ScrollHandler._reset()` — state leaks across tests otherwise. Files: `clamping` (rubber-band, the lazy `maxScrollY` cache), `frame-rate` (the frame-rate-independence proofs), `lifecycle` (subscribe/unsubscribe leaves nothing bound; an idle page costs zero frames), `quiet` (quiet windows, resize classification, rebase), `rest` (movement-armed rest — the subtlest thing in the module), `wakeup` (the `dt` ceiling after a backgrounded tab), `viewport-metrics` (metrics + the export-surface contract).

The engine and the components have **no unit tests** — they are verified in-browser (see above), because essentially all of their behavior is layout- and transform-dependent.
